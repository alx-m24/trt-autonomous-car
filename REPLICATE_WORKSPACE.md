# Replicating this ROS 2 Workspace on Another Computer

A step-by-step guide to get the `auto_drive` autonomous-RC workspace running on a friend's machine.

> **The one thing people miss:** the custom Gazebo track is **NOT in the repo** — it lives in
> `~/.gazebo/models/track_race/`. If you only copy the workspace folder, Gazebo will fail to load
> `model://track_race` and the world will be empty/broken. You must copy that folder too (Step 4).

---

## 0. What this workspace actually is

- **One ROS 2 package:** `auto_drive` (ament_python), in `src/auto_drive`.
- **Nodes:** `perception_node`, `control_node` (+ `parking_node`, `terrain_node`, `calibrate_perspective`).
- **Simulator:** Gazebo **Classic (Gazebo 11)** + `gazebo_ros` plugins.
- **Perception:** classical OpenCV (bird's-eye + lane/road masks). **No deep learning** — `yolov8n.pt` at the
  repo root and the `.venv/` are leftovers from unrelated experiments and are **not used**.

### Environment target (must match)
| Component | Version |
|---|---|
| OS | Ubuntu **22.04 (Jammy)** |
| ROS 2 | **Humble** |
| Python | **3.10** (system python, run ROS *outside* any venv) |
| Gazebo | **Classic 11** |

---

## 1. Install ROS 2 Humble (on the friend's machine)

Follow the official Humble desktop install for Ubuntu 22.04:
https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html

```bash
sudo apt update && sudo apt install -y ros-humble-desktop ros-dev-tools
```

Add sourcing to `~/.bashrc`:
```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

---

## 2. Install the system (apt) dependencies

These are the packages this workspace actually needs beyond base ROS:

```bash
sudo apt update && sudo apt install -y \
  ros-humble-gazebo-ros-pkgs \
  ros-humble-robot-localization \
  ros-humble-cv-bridge \
  ros-humble-turtlebot3-gazebo \
  python3-colcon-common-extensions
```

- `gazebo-ros-pkgs` — Gazebo Classic + ROS bridge (planar_move, camera, imu plugins).
- `robot-localization` — the EKF node (`ekf_node`) the launch file starts.
- `cv-bridge` — image conversion for the perception node.
- `turtlebot3-gazebo` — provides extra Gazebo models on `GAZEBO_MODEL_PATH` (matches the source env).

---

## 3. Install the Python (pip) dependencies

The perception node runs under **system python3** (ROS runs outside the `.venv`). It needs OpenCV + NumPy:

```bash
pip3 install "numpy==1.21.5" "opencv-python==4.11.0.86" "opencv-contrib-python==4.13.0.92"
```

> Note: `clean_requirements.txt` in the repo is a `pip freeze`-style dump that **mixes pip packages with
> ROS message packages** (e.g. `gazebo_msgs`, `rclpy`). The ROS ones come from the apt install in Steps 1-2 —
> do **not** try to `pip install` them. Only the three packages above are real pip dependencies.

---

## 4. Copy the custom Gazebo track model  ⚠️ critical, easy to miss

The world references `model://track_race`, which Gazebo resolves from `~/.gazebo/models/`. This folder
(~352 KB: `model.config`, `model.sdf`, `materials/scripts/track.material`,
`materials/textures/tracknxgv.png`) is **not part of the package**.

On the **source** machine, package it:
```bash
tar czf track_race_model.tar.gz -C ~/.gazebo/models track_race
```
On the **friend's** machine, extract it into the same location:
```bash
mkdir -p ~/.gazebo/models
tar xzf track_race_model.tar.gz -C ~/.gazebo/models
# verify:
ls ~/.gazebo/models/track_race   # -> materials  model.config  model.sdf
```

---

## 5. Transfer the workspace (package source only)

There is **no git repo** here yet, so use a clean tarball — and copy **only `src/auto_drive`**, never the
generated `build/ install/ log/` or the nested `src/build src/install src/log` cruft.

On the **source** machine:
```bash
cd ~/autonomous_prototype
tar czf auto_drive_src.tar.gz \
  src/auto_drive \
  CORNER_MANEUVER_SESSION.md REPLICATE_WORKSPACE.md STEERING_FIX_SUMMARY.md PERCEPTION_FIX.md
```

On the **friend's** machine:
```bash
mkdir -p ~/autonomous_prototype && cd ~/autonomous_prototype
tar xzf auto_drive_src.tar.gz
```

### Do NOT copy these (cruft / machine-specific / unused)
- `build/  install/  log/` and `src/build  src/install  src/log` — regenerated by colcon.
- `.venv/` and `yolov8n.pt` — unrelated experiments, not used by these nodes.
- The custom CycloneDDS under `/home/jackerost/install/cyclonedds` — leftover from another project;
  `RMW_IMPLEMENTATION` is unset (default DDS), so it is **not** needed here.

### (Recommended) Make it a git repo instead
For repeatable future syncs, initialise git and push to GitHub, then the friend `git clone`s:
```bash
cd ~/autonomous_prototype
printf "build/\ninstall/\nlog/\nsrc/build/\nsrc/install/\nsrc/log/\n.venv/\n*.pt\n__pycache__/\n" > .gitignore
git init && git add src/auto_drive *.md .gitignore && git commit -m "auto_drive workspace"
# then: git remote add origin <url> && git push -u origin main
```
(The `track_race` model in `~/.gazebo` still has to be transferred separately — Step 4.)

---

## 6. Build

```bash
cd ~/autonomous_prototype
source /opt/ros/humble/setup.bash
colcon build --packages-select auto_drive
source install/setup.bash
```

Expect: `Finished <<< auto_drive`.

---

## 7. Run & verify (3 terminals — each: `cd ~/autonomous_prototype && source /opt/ros/humble/setup.bash && source install/setup.bash`)

```bash
# T1 — Gazebo + EKF
ros2 launch auto_drive mycar_autorace.launch.py
#   if the car/camera look frozen, physics may be paused:
ros2 service call /unpause_physics std_srvs/srv/Empty

# T2 — Perception (headless = faster; drop 'env -u DISPLAY' to see the debug windows)
env -u DISPLAY ros2 run auto_drive perception_node \
  --ros-args -p bird_m_per_px_x:=0.0006 -p bird_m_per_px_y:=0.002

# T3 — Control
ros2 run auto_drive control_node
```

Quick health checks:
```bash
ros2 topic echo /front_camera/image_raw --once --field height   # camera alive (-> 480)
ros2 topic hz /lane_path                                         # ~30 Hz = perception healthy
ros2 topic echo /odometry/filtered --once                       # EKF publishing
```

---

## 8. Gotchas (learned the hard way)

- **Empty/black world** → the `track_race` model wasn't copied to `~/.gazebo/models/` (Step 4).
- **Everything frozen, no `/clock`/camera** → physics is paused: `ros2 service call /unpause_physics std_srvs/srv/Empty`.
- **Never `pkill gzclient`** — when launched via the `gazebo` wrapper, killing the GUI also kills the server (exit 255). Ctrl-C the launch instead.
- **`ros2 run` "command not found"** → you're inside a Python venv. `deactivate`, then re-source ROS.
- **Perception slow / GUI heavy** → run perception headless (`env -u DISPLAY ...`); it skips the 3 debug windows.
- `gazebo: command not found` → `sudo apt install gazebo` (Classic 11).
